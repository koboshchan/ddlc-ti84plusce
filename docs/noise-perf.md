The October 13 noise optimization preserves the existing sparse 2x2 ordered-alpha renderer exactly. It does not replace it with a full-screen blend or a different random sequence.

The assembly now processes 16 blocks with fixed IX/IY displacements, then advances both framebuffer pointers by 32 bytes. Register counters replace per-block RAM-counter loads. The recurrence, coverage threshold, mask, palette lookup and four-byte undo ordering are unchanged. The C change only scopes host-only variables to the host branch. GNU assembler macros keep the repeated instruction bodies readable.

Fresh standalone CEmu runs at clock48 compared the pre-change source copied directly from the worktree against the final adopted source. All 41 elapsed times from 0 through 4000ms, in 100ms increments, matched an independent per-pixel oracle for all 76,800 framebuffer bytes and restored every original byte. There were zero errors in each run. The worst draw changed from 100.2808ms to 64.0259ms, restore from 69.5496ms to 38.6353ms, and same-frame draw plus restore from 169.8303ms to 102.6611ms, a 39.55% reduction. These are noise-only timings, not whole-game frame timings.

A separate final-kernel run passed 24 cases including 749/750/751, 1499/1500/1501, 2249/2250/2251, 2999/3000/3001ms, 65535ms, 100000ms and the 24-bit maximum 16777215ms. It had zero pixel or undo errors. The emulator's entire loaded noise text was compared with the assembled executable, allowing only the documented coverage-immediate patches, not just matching a launcher or entry signature. Raw rows and executable text hashes are in noise-perf-48mhz.json.

The assembly text increases from 329 to 2086 bytes. Removing eight unused data bytes makes the benchmark's net program increase 1749 bytes. No additional working RAM or undo allocation is needed. The serial, non-reentrant, writable-RAM execution requirement already existed because of the patched CP immediate. IX/IY are preserved; the CEdev caller-clobbered shadow BC counter is used only inside the draw function.

A 32-block development variant only improved the earlier 16-block worst combined timing by about 1.16ms while adding another roughly 1.75KB of text, so 16 is the chosen compromise. That comparison is from prior development runs, not the fresh paired benchmark.

An exact cyclic ring was investigated rather than assuming short random periods. The LFSR has all 65535 nonzero states. A five-bit packed ring alone needs 40960 bytes, or 65535 bytes as directly indexed bytes. A direct uint16 seed-to-phase map adds 131070 bytes. Sequential phase search or a compressed phase map would require additional machinery and measurements. This is not adopted because the pointer/counter optimization improves speed without extra RAM or archive assets. The complete-period sliding-window host test proves the maximum selected blocks in any 19200-draw window is 4988, retaining the existing 19952-byte undo bound.
